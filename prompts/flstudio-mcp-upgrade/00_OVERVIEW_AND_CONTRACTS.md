# fl-studio-mcp — доработка MCP-сервера: нулевой контекст и контракты

> Этот файл — «нулевой» контекст. Его дают каждому агенту (реализация / ревью / функциональный
> тест) **первым** и держат в контексте всех последующих сессий. Он фиксирует решения, слои,
> контракты, известные ограничения FL API и результаты предыдущей рабочей сессии, чтобы у
> исполнителей не было разночтений.
>
> Комплект: `00_OVERVIEW_AND_CONTRACTS.md` (этот файл) → `01_IMPLEMENTATION_PROMPTS.md`
> (эпики с DoD) → `02_REVIEW_PROMPTS.md` (промпт ревью-агента на каждый эпик) →
> `03_QA_PROMPTS.md` (промпт функционального теста на каждый эпик).
>
> Перед началом работы исполнитель читает `README.md`, `CONTRIBUTING.md` и `ROADMAP.md` в корне
> репозитория. Порядок эпиков — в конце `01`.

## 0. Фиксированные решения

| #   | Решение                     | Значение                                                                                                                                                          |
| --- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Платформы                   | Разработка и живые тесты — **macOS** (FL Studio 2026 v26.1.7). Код пишется кроссплатформенно (Windows-ветки не ломать), но живая верификация только на macOS.       |
| D2  | Транспорт                   | MCP-инструменты идут через `connection.get_bridge()`: `FLSTUDIO_MCP_TRANSPORT=tcp` → `TCPBridge` (демон, JSON over TCP `127.0.0.1:9787`), иначе прямой SysEx-мост. Новые тулы **никогда** не открывают порт сами. |
| D3  | Протокол                    | `src/fl_studio_mcp/protocol.py` (константы `CMD_*`, `PROTOCOL_VERSION = 2`) ↔ `_HANDLERS` в `fl_controller/FLStudioMCP/device_FLStudioMCP.py`. Любая новая команда добавляется **в оба файла в одной правке**. Аддитивные команды версию не поднимают; изменение семантики/формата существующей команды — поднять до 3 и синхронно в обоих файлах. |
| D4  | Бюджет SysEx                | Ответ — один пакет `data` ≤ **600 байт** JSON (`_LIST_BUDGET` в контроллере; у `plugin_get_params` ~480). Любая новая выборка с неограниченным числом элементов — **обязана** пагинироваться (`next_start`/`start`) через `fetch_all_pages`. |
| D5  | Безопасность записей        | Любая MCP-запись — только через `safety.safe_write` / `safety.safe_write_group` (снимок → changelog `~/.flstudio-mcp/changelog.jsonl` → readback → rollback через `fl_rollback_last_change`). Новый тип состояния = **новый scope в `take_snapshot()`** в той же правке. `fl_set_dry_run(True)` обязан работать для нового write-тула. |
| D6  | Именование                  | MCP-тулы `fl_*` в `src/fl_studio_mcp/tools/*.py`, `register(mcp)` в конце файла, аннотации `_RO`/`_WR`, docstring с аргументами и возвращаемым значением. RPC-команды — `snake_case` без префикса. |
| D7  | Проверки                    | `ruff check .` (line-length 100, py310, select E,F,I,B,UP,SIM) чистый. Живые проверки — standalone-скрипты `scripts/test_*.py` (нужен открытый FL + контроллер), минимум `python scripts/test_bridge.py` не должен ломаться. Юнит-тестов пока нет — их вводит E-8 (fake-bridge). |
| D8  | Документация на эпик        | Каждый эпик обновляет соответствующие разделы: `README.md` (таблица инструментов + Limitations), `skills/flstudio-production/SKILL.md` (как пользоваться), `ROADMAP.md` (галочка). |
| D9  | Без обхода ограничений      | Ограничения FL (см. §3) не обходятся через ненадёжные трюки (сырой pyautogui-клик, координатные выстрелы) без доказательства надёжности в E-0. Противоречивые факты (file I/O в pyscript-песочнице) сначала **проверяются спайком**, потом только на них строится код. |
| D10 | Язык                        | Промпты и вывод агентов — русский. Код, docstring, README — английский.                                                                                            |

## 1. Архитектура (слои и файлы)

```
MCP-клиент (агент)
  └─ src/fl_studio_mcp/tools/*.py      # 67 fl_* инструментов, register(mcp)
       ├─ safety.py                    # safe_write / safe_write_group / take_snapshot / rollback
       ├─ protocol.py                  # CMD_* константы, PROTOCOL_VERSION=2, port_*_name()
       └─ connection.py                 # get_bridge() -> FLBridge (SysEx) | TCPBridge (демон :9787)
            └─ daemon.py               # JSON+ "\n" RPC-сервер (fsck: fl-studio-mcp-daemon)
                 └─ MIDI SysEx → fl_controller/FLStudioMCP/device_FLStudioMCP.py
                      └─ _HANDLERS: cmd → FL Python API (mixer/channels/plugins/ui/…)
```

Параллельный ветвь (запись нот в Piano Roll, **не** через SysEx):

```
FLBridge.apply_notes → pyscript_gen.py генерирует MCP_Apply.pyscript (ноты вшиты литералом)
  → pyscript_trigger.py шлёт хоткей «Run last script again» (macOS: Cmd+Opt+Y)
  → FL читает файл заново и применяет ноты
```

Текущая карта (82 тула, 53 RPC-хендлера; счётчики: `grep -c "@mcp.tool"` по
`src/fl_studio_mcp/tools/`, regex `"([a-z_]+)": _h_` по `_HANDLERS`) — в `README.md`.
Дыры E-2/E-5 закрыты (см. `docs/E2_REPORT.md`, `docs/E5_REPORT.md`): `pattern_*`,
`plugin_preset`, `api_probe`, `channel_get_color`, `mixer_get_color` — все имеют
MCP-тулы. `fl_undo` и пресетная навигация сознательно ВНЕ safety-слоя (снапшот
нечитаем / restore недостоверен) — предупреждения в ответах и докстрингах.
Нотный мост (E-6, `docs/E6_REPORT.md`): `applied` всегда честный `"unknown"`
(песочница блокирует файлы; контроллер не импортирует `flpianoroll` — оба
факта доказаны). `triggered` = «хоткей отправлен», не «ноты применились`.
Чтение score из Piano roll **BLOCKED** (E-7, `docs/E7_REPORT.md`): нет
читаемого API нот ни в контроллере (полный probe всех модулей), ни в
песочнице наружу — `unknown` permanent до смены фактов FL.
Мёртвое объявление
`plugin_list_params` удалено из `protocol.py` (покрыто `plugin_get_params`).

## 2. Контракты, которые обязан проверять каждый ревьюер

1. **Protocol sync**: каждая новая `CMD_*` есть и в `protocol.py`, и в `_HANDLERS`; имя строки
   совпадает буквально; тест — `grep` по обоим файлам.
2. **Бюджет ответа**: любая новая выборка ≤600 байт или пагинирована; `fetch_all_pages`
   используется там, где число элементов не ограничено.
3. **Write-путь**: каждый write-тул — `safe_write`/`safe_write_group`, корректный `scope`
   (существующий kind в `take_snapshot` или новый — добавлен в той же правке), есть
   `build_restore`, dry-run возвращает `planned` без побочных эффектов, ответ содержит
   `before`/`after` из **свежего** readback (не echo того же тика).
4. **Живой readback и пейсинг**: записи к плагинам выдерживают паузу 0.3–0.5 с между вызовами
   (через `time.sleep` в батч-туле или инструкцией агенту); результат сверяется повторным чтением
   с допуском ±0.02 — расхождение возвращается явно (`verified: false` + hint), а не молча.
5. **Кроссплатформенность**: никаких чисто-win32 API без `sys.platform`-проверки; macOS-путь
   обязателен.
6. **DoD-доказательства**: из `01` — команды проверки выполнены и их вывод процитирован в отчёте.

## 3. Подтверждённые ограничения FL API (не обходить, документировать)

- Нельзя загружать новые VST/AU — только контроль существующих плагинов.
- Нельзя размещать клипы в плейлисте, рендерить, читать аудиовыход.
- Паттерны: создание — только `findFirstNextEmptyPat`/клон (`arrange_*`); «с нуля» из API нельзя.
- Запись темпа игнорируется при открытом модальном диалоге FL.
- **Pickup mode**: запись параметра плагина игнорируется, пока окно плагина открыто (ручка
  «ждёт» mouse-drag). Рабочий рецепт: закрыть окно плагина → писать по одному с паузой →
  проверять свежим чтением.
- Ступенчатые параметры (типы дисторшна A/B/C и т.п.) API не принимает — только мышью.
- Гонки: две быстрые записи подряд на одном параметре коалесцируются; `_verify_retry` в
  `safety.py` решает это для toggle-записей, для плагинов — пейсинг (D5, п.4).
- **Piano-roll pyscript-песочница**: импортируется только модуль `flpianoroll`; `mixer`,
  `plugins`, `channels`, `ui`, `transport` — падают (проверено флажками-нотами). File I/O в
  песочнице считался заблокированным (проба `MCP_Read_Probe`, FL 25.2.5) — **противоречит**
  (см. `docs/architecture.md`) противоречит `pyscript_gen.py` («blocked… confirmed by probe»);
  перепроверка на FL 26 — задача спайка E-0.
- Потолок MCP: нельзя создавать новые плагины/паттерны с нуля через сервер (см. секцию
  LIMITS в `src/fl_studio_mcp/server.py`),
  есть `fl_arrange_new_pattern`/`fl_arrange_clone_pattern` как обход штатными API.
- Хоткей «Run last script again» на macOS (Cmd+Opt+Y через pyautogui/osascript) в предыдущей
  сессии **не срабатывал** надёжно; раз в сессию пользователь запускает «MCP Apply» вручную из
  меню Piano roll → Tools → Scripts. Нет API для «arm» скрипта.

## 4. Что уже известно из рабочей сессии (не переоткрывать)

- `plugin_set_param` работает через RPC, но требует рецепта из §3 (закрыть окно, паузы,
  сверка); MCP-туйл `fl_plugin_set_param` возвращает `before`/`after`, но **не** детектирует
  неудачу (verified отсутствует) — чинит E-1.
- Измеренные уровни (дроп bro-step, 145 BPM): Insert 6 peak −4.76 dB, Master −0.19 dB
  (почти клип; мастер рекомендуется опустить до ~−3 dB).
- `transport_play` в RPC **нет** — воспроизведение только `fl_play`/`fl_stop`.
- Прямой RPC-доступ для отладки: `echo '{"cmd":"..."}' | nc 127.0.0.1 9787` или
  `scripts/test_bridge.py`; ответ `{"ok":true,"data":{...}}` / `{"ok":false,"error":...}`.
- Демон живёт отдельно от MCP-сервера; heartbeat стареет >3 ч при открытом FL — обычно
  модальный диалог/свораченный FL/остановленный контроллер. `fl_ping` — первая команда при
  любой «мёртвости» моста.

## 5. Предпосылки живых тестов (общие для 01/03)

1. FL Studio открыт, контроллер FLStudioMCP подключён (MIDI in/out, порт совпадают).
2. `fl_ping` → `ok: true`, heartbeat свежий. Демон: `fl-studio-mcp-daemon` запущен,
   `FLSTUDIO_MCP_TRANSPORT=tcp`.
3. Перед любой записью — `fl_take_snapshot`/`fl_set_dry_run(True)` для предпросмотра.
4. После теста — состояние проекта вернуть (`fl_rollback_last_change` / ручной откат),
   не оставлять мусорные паттерны/маркеры/ноты.
